# ECPAF-V2.2 persistent execution admission

**Status:** development pilot, draft PR. **Certification:** WITHHELD.

## Purpose

This adapter converts a previously approved, immutable task graph into bounded, resumable execution invocations. It can be called by macOS `launchd` or another authorized persistent worker. It does not plan new tasks, request approvals, modify permissions, merge pull requests, deploy software, or certify the eight-repository federation. TheHub retains cross-repository governance; repo-specific authority remains local.

## Mandatory preflight

An admission JSON manifest freezes `epoch_id`, UTC start/end (180–240 minutes), polling interval (30–300 seconds), exact SHA-256 of the plan, dispatcher and writer, count of authorized jobs (maximum 12), disk reserve (at least 2 GiB), and `DRAFT_PR_ONLY` as the **sole** execution mode. Its protected operations array must be empty and certification must be `WITHHELD`. Task manifests are individually hashed and may not expand the authorized scope. These limits are enforced with exceptions, not Python assertions.

Use the reviewed `ecpaf-v2.2-dispatch/1` DAG generated by `ecpaf_task_dispatcher.py`. Keep admission and every referenced file in the same dedicated source folder. Never place untrusted or mutable files there. The adapter cannot by itself authenticate the human who admitted the plan: a trusted admission process is required before any unfinished queue is enabled.

## State and recovery

Each tick obtains a singleton lock, validates the SQLite ledger and every historical receipt hash/reference, verifies the admission and task bytes, and checks its resource budget before launching the bounded dispatcher. SQLite uses WAL and `synchronous=FULL`; receipts are SHA-256 content-addressed. After restart, a changed admission fails closed. The existing dispatcher reconciles in-flight writer operations and does not blindly retry ambiguous pushes or PR creations.

On expiry exactly one `EXPIRED` receipt is created. Subsequent calls return `ALREADY_EXPIRED` and perform no dispatch. Resource exhaustion records `RESOURCE_BLOCKED`; an unexpected dispatcher exit records `RECONCILIATION_REQUIRED`; corrupted evidence stops the tick with nonzero exit status. The external scheduler can retry a safe blocked tick within the admission window, but must never manufacture approvals or replace the frozen plan.

## Example invocation

`python3 tools/afk/ecpaf_persistent_executor.py --admission /trusted/frozen/admission.json --state-dir /durable/ecpaf/epoch-001`

A launchd job may invoke this command every 120 seconds **only when the plan is already authorized**. Do not enable the new runner merely because this PR merges. Configure and test an explicit task queue, authorization provenance, heartbeat monitoring, disk-pressure suspension, resume and end-of-window receipts first.

## Acceptance limits

The unit suite includes admission, replay, expiry, tampering, storage, singleton, and failure-reconciliation fixtures. The previous 3-hour scheduled pilot (91 PASS + 1 EXPIRED) replayed a completed queue; it is not evidence of 180 minutes of autonomous unfinished coding. Full AFK-95 certification requires genuine cross-session durability, simulated and actual worker restarts, browser disconnect and host reboot recovery, duplicate-mutation safety, authorization gates, evidence integrity, and exact-head CI/LOCKSTEP.
