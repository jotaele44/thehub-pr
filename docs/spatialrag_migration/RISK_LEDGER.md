# Risk Ledger

Phase 0 audit deliverable. Companion to [ADR 0003](../adr/0003-evidence-intelligence-control-plane.md).

| Risk | Likelihood | Impact | Mitigation phase |
|---|---|---|---|
| Hardcoded default DB credentials (`spatial_rag`/`spatial_rag`) ship into a shared environment because they were never removed before deploy | Medium — the exact failure mode default-credential incidents usually take | High — direct database compromise | Phase 1 ([`SECURITY_MODEL.md`](SECURITY_MODEL.md)) — credentials removed from any committed example file before the new datastore is provisioned |
| HyDE-on-by-default silently sends forensic/FOIA document text to a third-party LLM API before a user makes any explicit choice | High if the default were ported unchanged — spatial-rag's `HYDE_ENABLED=True` is the shipped default | High — data-handling/exfiltration concern for sensitive source material, independent of retrieval quality | Phase 1 — `hyde_enabled=false` is a contract invariant on every default `RetrievalProfile`, verified by a binary parity gate, not a configuration convention that can silently drift |
| MMR reranker's dead-code wiring (`chunk_embeddings={}` at the actual call site) gives false confidence that result diversity is happening when it is not | Confirmed present today, not hypothetical | Medium — degrades answer quality without any visible failure signal | Phase 2 — rebuilt fresh against real embeddings, with a contract test that would have caught the empty-dict bug, per [`COMPONENT_MIGRATION_MATRIX.md`](COMPONENT_MIGRATION_MATRIX.md) row 8 |
| Keyword-based evidence tiers get trusted as authoritative if ported without the provisional/certified split | High if ported naively — the mechanism is simple to copy, the guardrail is easy to skip | High — false certainty in evidence quality directly undermines the system's forensic purpose | Phase 1-2 — `tier_review_status` is a required field on every tier record from the first schema, not an optional addition |
| Committed `.pytest_cache/` and malformed brace-expansion directories signal the package wasn't carefully reviewed before upload, raising the prior on other undetected issues beyond what this audit found | Confirmed present; the *implication* (undetected issues) is the residual risk | Medium — this audit is thorough but not exhaustive; treat spatial-rag's code as needing independent verification component-by-component, not batch trust | Ongoing — every `ADAPT`/`ADOPT` row in [`COMPONENT_MIGRATION_MATRIX.md`](COMPONENT_MIGRATION_MATRIX.md) is independently reviewed at extraction time, not waved through because it passed this audit's file-level read |
| Single hardcoded model string (`claude-3-5-haiku-20241022`) creates a reproducibility/availability risk — no `model_revision` field, no fallback provider | Medium — model deprecation/retirement is a routine occurrence, not a hypothetical | Medium — historical answers become unreproducible or generation silently fails when the hardcoded model is retired | Phase 1-2 — `LLMProvider` abstraction with recorded `model_revision` per [`DATA_CONTRACTS.md`](DATA_CONTRACTS.md) §10 |
| Postgres/PostGIS/pgvector introduced as a wholly new ops datastore dependency for thehub-pr, which runs a single SQLite-backed service today | Certain if [`DATABASE_BOUNDARIES.md`](DATABASE_BOUNDARIES.md)'s recommendation is adopted | Medium — new operational surface (backups, availability, credential rotation) that thehub-pr's current `docker-compose.yml` (one service) doesn't have | Phase 2 — explicit operational runbook required before this datastore is provisioned outside a dev environment; tracked as an open question in [`READINESS_REPORT.md`](READINESS_REPORT.md) |
| DB-backed integration test paths in spatial-rag have no verified passing evidence (excluded from the "126 tests passing" claim), so any code ported from those paths carries unverified correctness | Confirmed — `conftest.py` requires a live fixture DB with no skip markers, and no CI run evidence for that path was found in the package | High for anything classified ADAPT/ADOPT in the ingestion or retrieval SQL paths specifically | Phase 2 — new integration tests written against the new snapshot schema before any such path is trusted, per [`PARITY_GATES.md`](PARITY_GATES.md) |
| Contradiction-preserving entity resolution is new-build (neither codebase has it today); under-scoping it risks silently reintroducing name/coordinate/co-occurrence-only merging | Medium — this is the kind of requirement that erodes under implementation time pressure | High — silent entity merges are exactly the failure mode item 11 of the mission exists to prevent | Phase 2 — `entity_identity_decision` requiring an explicit reason code is a schema-level constraint, not a code-review convention, per [`DATA_CONTRACTS.md`](DATA_CONTRACTS.md) §5 |
